# Проверка режима заказов по ценам ERP — 26 октября 2026

Изменения проверены локально на 1С:Элемент Script 10.0.2_1.
Действующие приложения и реальные базы ERP при этих проверках не изменялись.

## Выполненные проверки

- `scripts/test_price_orders.py --runtime <ElementScript>`:
  400 сценариев исходного XBSL-расчёта. Оба алгоритма, разные цены, влияние
  средней цены на спрос, равные цены, минимум для каждой команды, нулевой
  исходный спрос, разные стартовые запасы, потолок стартового спроса,
  невозможные начальные условия, последующие заказы без товара на складе,
  перестановка команд и повтор расчёта.
- В том же запуске исполняется исходный метод публикации заказов с заменой
  только обращений к хранилищу: ровно один заказ на команду, объединение
  положительных строк, описание, суммы, устойчивые идентификаторы,
  сохранение источников и запрет повторной публикации.
- `scripts/test_market_odata.py --runtime <ElementScript>`:
  221 обращение к локальному HTTP-имитатору ERP. Чтение настоящим XBSL-методом
  четырёх цен, отдельное чтение без склада, ожидание завершения команды,
  фиксация цены, аренда чтения, ошибки/восстановление, отклонение старого
  токена и пауза. Проверен исходный цикл новых фаз, в том числе явный срок
  установки цен 0 минут и резервный срок продаж.
- Тем же тестом проверена отправка одного многострочного заказа ERP:
  две модели, три единицы, сумма 160 000 ₽, повтор без дубля. Прежние проверки
  общего рынка, таймаутов, прав кабинета, статусов, потерянных ответов,
  проведения, НДС и заказов для будущего производства также проходят.
- `xbsl-validate` по всему проекту: 132 YAML-файла, 0 ошибок.
  48 предупреждений о неполном покрытии валидатора и типах файлов,
  проверяемых другими средствами. Это не полная компиляция приложения.
- `git diff --check`: ошибок форматирования нет.

## Границы проверки

UI нового режима не проходил браузерный прогон в опубликованном приложении.
Полная сборка проекта и проверка на действующих ERP требуют публикации новой
версии. Сетевые тесты использовали только 127.0.0.1; новых заказов в реальных
базах они не создавали.
