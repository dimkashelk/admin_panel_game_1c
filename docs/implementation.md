# План реализации

Проектирование выполнено для Элемента 10.0. В ветке `dev` создан каркас метаданных существующего проекта `dimkashelk/Игра`; локальная проверка YAML и связей пройдена. Сборка `1.0-4` успешно применена к тестовому приложению Элемента `10.0.3-20`. Следующая работа — бизнес-логика, формы и интеграция с конкретной ERP. Документация не является подтверждением сборки или работы приложения.

## Применение навыков XBSL

1. Существующий проект `dimkashelk/Игра` взят из актуальной ветки `dev`; его идентификатор, имя и версия сохранены. Инициализация нового проекта не требуется.
2. `xbsl-subsystem-add`: создать подсистемы по направленному графу архитектуры.
3. `xbsl-explore`, `xbsl-meta-add`, `xbsl-uuid`: создавать объекты в порядке зависимостей, проверяя имена и UUID.
4. `xbsl-pattern-rls`: реализовать доступ ведущего по назначенной игре и ограничение сервисного пользователя своим участником.
5. `xbsl-form-info`, `xbsl-form-add`, `xbsl-form-dashboard`: создавать формы по уже существующим полям и namespace.
6. `xbsl-validate`: проверить метаданные. Затем отдельно скомпилировать и запустить: локальная YAML-проверка не проверяет весь XBSL и платформенный runtime.

Новые проекты целятся в `РежимСовместимости: 10.0`; точная `technology-version` облачного приложения выбирается отдельно. UUID не меняются при последующих доработках.

Серверные транзакции, блокировки, HTTP-клиент, безопасное хранение секретов и расписания повторной обработки проверяются по документации и стенду точной сборки. Публичные страницы справочника Element 10 в ходе проектирования не удалось открыть веб-инструментом; ограничения метаданных и форм проверялись по предоставленным локальным reference-файлам навыков. Это не заменяет проверку компилятором.

## Проверки реализации

| Область | Сценарии |
|---|---|
| Рынок | Граничные запасы, равные цены, ограничение количества, округление общей суммы, перестановка строк, повтор расчёта |
| Игра | Два ведущих одновременно меняют фазу, старый токен, повтор запуска, пауза и возобновление |
| Обмен | Потеря ответа после успешного создания заказа, повтор сообщения, тот же ключ с другим телом, частичный успех |
| ERP | Цены и запасы из одной фиксации, неверное соответствие, характеристика, единица, частичная реализация |
| Финансы | Оплата только фактической реализации, несколько платежей, долг поставщику, подтверждение закрытия месяца |
| Изоляция | Сервис пытается обратиться к чужому binding, ведущий к чужой игре, наблюдатель к незавершённым предложениям |
| UI | Мастер подготовки, пульт, диагностика ошибки, рейтинг, работа после перезагрузки клиента |

Проверка на ERP выполняется в изолированной учебной копии. Тесты на стенде проверяют реальные документы и остатки, а не только успешный HTTP-ответ.

## Вопросы перед бизнес-логикой и проверкой на стенде

Проект уже определён: поставщик `dimkashelk`, имя `Игра`, режим совместимости `10.0`.
- Точная сборка Элемента 10, способ размещения и тестовый контур.
- Релиз ERP, платформа 8.3, адрес тестовой публикации и возможность установить расширение.
- Размещение команд: отдельные базы или области общей базы.
- Выбранный профиль производственной спецификации: упрощённый одноэтапный или подробный маршрут.
- Подтверждение проектных правил из таблицы выше.

## Источники требований

| Материал | Использованная часть |

| Требования к предварительной настройке системы.docx | НСИ, склады, покупатель, поставщик, планы, упрощённая спецификация |

| Модель рынка.xlsx | Подробная спецификация с работами и расходниками |
| bike_assembly_full.xlsx | Операции, материалы, рабочие центры |
| game_simulation_overview.docx | Образовательные сценарии использования |

Дополнительно обнаружены расхождения исходников: краткое описание предполагает стартовые ресурсы со случайностью, Excel — готовые ресурсы без денег; подробный маршрут содержит нормы времени, а настройка ERP исключает рабочие центры и трудоёмкость. В номенклатурном Excel есть BOM только CityRide, поэтому это не полный пакет для настройки четырёх моделей. Эти материалы нельзя считать единой утверждённой спецификацией без выбора профиля.

## Выполнено: первый этап метаданных

Созданы 29 объектов: 7 справочников, 3 документа, 11 перечислений и 8 независимых регистров. Подготовлены все 5 подсистем. `СнимкиERP`, `РасчетыРынка` и `СобытияИгры` реализованы документами; платежи выделены в отдельный регистр. Подробности, права и границы реализации — в [каркасе метаданных](metadata.md).

Проверены 35 YAML-файлов; ошибок нет. Шесть предупреждений валидатора относятся к структурным описаниям проекта и подсистем. Дополнительная проверка контролирует UUID, ссылки, граф зависимостей, перечисления, индексы и одинаковую структуру настроек сценария и игры. Компиляция и запуск сборки `1.0-4` выполнены на Элементе `10.0.3-20`, задача обновления завершена успешно.
