# Создание игры и настройка сохранённой игры

В меню есть два отдельных сценария: **«Новая игра»** создаёт игру, **«Настройка игры»** редактирует существующую. Из пульта кнопка **«Настройка этой игры»** открывает настройки выбранной игры. На этих формах и в окне настройки команды нет сворачиваемых блоков.

## Новая игра

1. Укажите название и выберите сценарий. Seed и режим общего рынка находятся в общей группе правил. По умолчанию Seed = 42 и включён общий рынок.
2. В таблице уже есть **«Команда 1»** и **«Команда 2»**. Добавьте или удалите строки стандартными командами таблицы. Требуется минимум две команды с уникальными названиями.
3. Откройте **«Настроить команду»** карандашом в строке. Поле **«Наименование»** содержит текущее название: измените его и нажмите **«Готово»**. Игроки и ERP не обязательны для создания игры.
4. Нажмите **«Создать игру»**. Игра, команды, назначения игроков и подключения записываются в одной транзакции. Профиль игры с календарём и начальными данными сохраняется автоматически. После успеха открывается отдельная форма настройки созданной игры. При ошибке черновики остаются для исправления.

Столбец **«Игроков»** доступен только для чтения. Значение обновляется по фактическому составу команды после нажатия **«Готово»** в её настройках.

## Существующая игра

Выберите игру в разделе **«Настройка игры»**. Команды показаны таблицей; карандаш в строке открывает карточку с текущим наименованием, игроками и ERP. Для переименования измените поле **«Наименование»** и нажмите **«Готово»**. Команда **«Добавить команду»** в панели таблицы открывает такую же пустую карточку. Название, состав и подключение записываются в одной транзакции; закрытие карточки без сохранения отменяет изменения.

Правила, добавление и переименование команд доступны администратору до подготовки игры. Правила сохраняются кнопкой **«Сохранить настройки игры»**. Отдельного блока добавления и переименования команд нет.

Через **«Открыть расширенные настройки игры»** доступны три вкладки:

- **Доступ** — таблица назначений ведущих и наблюдателей. Добавление открывается командой панели, редактирование — карандашом строки. Для отключения снимите **«Активно»** в карточке назначения. Пользователь и роль существующего назначения фиксированы; другую роль добавьте отдельной строкой.
- **ERP команды** — выбор команды, адрес HTTP-сервиса ERP для фаз и итогов и таблица соответствий номенклатуры. Сервисный пользователь Элемента не требуется; сервис использует сохранённые учётные данные ERP. Команды обновления и сохранения соответствий находятся в панели таблицы. Импорт JSON скрыт в свёрнутом блоке. Подключение ERP редактируется в основной карточке команды.
- **Профиль игры** — сохранённые календарь и начальные данные JSON, с командой сохранения.

Назначения и соответствия изменяет администратор. Переход к пульту выполняется отдельной кнопкой; настройки не запускают игру автоматически.

## Игроки команды

Вкладка **«Игроки команды»** содержит редактируемую таблицу активных игроков. Добавляйте строку стандартной командой таблицы и выбирайте пользователя в ячейке. Стандартная команда удаления есть в строке и для отмеченных строк. Пустые строки и повтор одного пользователя не допускаются.

Изменения таблицы применяются по общей основной кнопке **«Готово»**. Для сохранённой игры удаление строки отключает назначение пользователя в этой команде, сохраняя его назначения в других командах. Для новой игры состав сохраняется в черновике команды и записывается при создании игры. Закрытие крестиком отменяет несохранённые изменения таблицы и параметров ERP.

В сохранённой команде команда **«Создать нового пользователя»** в панели таблицы открывает отдельное окно логина и пароля. Укажите пароль длиной от 8 символов либо оставьте поле пустым для генерации. Кнопка **«Создать»** сразу создаёт пользователя, назначает его команде и добавляет строку в таблицу. Пароль показывается открытым текстом через `Сообщить()` вместе с логином. Это отдельное действие не отменяется закрытием карточки команды. При первом входе игрок меняет временный пароль.

Создание игр, изменение состава и управление пользователями доступны администратору. Ведущий может настраивать ERP своей игры без изменения списка игроков.

## База ERP команды

1. Введите **адрес публикации ERP**, затем **логин** и **пароль**. Полный адрес OData формируется автоматически добавлением `/odata/standard.odata/`.
2. После изменения пароля система загружает доступные организации. Для повторной загрузки есть кнопка **«Загрузить организации»**. Список читается из ERP, с учётом прав указанного пользователя, без помеченных на удаление организаций и с постраничным чтением.
3. Выберите организацию из списка. Произвольный ввод запрещён. Если выбор пуст и организация одна, она выбирается автоматически. Смена адреса базы очищает выбор; смена логина или пароля сохраняет выбранное название и требует проверки списка перед записью новых параметров.
4. Нажмите общую кнопку **«Готово»**, чтобы сохранить ERP вместе с составом команды. Отдельной кнопки сохранения базы нет. При ошибке окно остаётся открытым, введённые данные сохраняются для исправления.

При открытии сохранённой команды организация сразу берётся из настроек; запрос ERP при открытии не выполняется. Ошибка загрузки организаций не стирает сохранённый выбор. Если выбранная организация отсутствует в новом ответе ERP, форма показывает сообщение и сохраняет название для проверки; изменённые параметры нельзя записать, пока не выбрана доступная организация.

В сохранённой команде показывается адрес публикации без OData-суффикса. Сохранённый пароль не возвращается на клиент: пустое поле сохраняет его при неизменном адресе и логине. Для получения организаций сервер использует сохранённый секрет. При изменении адреса или логина требуется новый пароль. Неизменное сохранённое подключение позволяет записать изменения состава даже при недоступной ERP. Команда без подключения не требует заполнения ERP для изменения имени или игроков.

Каждая команда игры использует отдельный адрес ERP. После подготовки адрес и организацию менять нельзя. Кнопка **«Подготовить или проверить базу»** работает с уже сохранённым подключением. В открытом окне команда и организация уже выбраны, пустой пароль использует сохранённый секрет. После «Создать необходимые данные» или чтения готовой базы все 15 идентификаторов ERP сохраняются автоматически для этой команды; новые параметры сначала запишите через **«Готово»**. Полный цикл игры требует HTTP-сервиса расширения ERP по [исходящему контракту](erp-pull.md). Адрес сервиса задаётся на вкладке «ERP команды» расширенных настроек; по умолчанию используется `/hs/game/v1/` этой базы.

## Проверка после публикации

1. Откройте карандашом команду с настроенной ERP: организация видна сразу. Закройте и откройте её повторно, в том числе при недоступной ERP. Измените только имя или состав игроков и сохраните — организация должна остаться прежней.
2. Смените пароль ERP: после успешной загрузки прежняя доступная организация остаётся выбранной. При ошибке или отсутствии организации в ответе название не исчезает, новые параметры нельзя сохранить. Смена адреса очищает выбор.
3. Создайте пользователя через панель таблицы: проверьте строку игрока, сообщение с логином и открытым паролем, затем первый вход. Повторный логин и короткий пароль оставляют окно открытым с ошибкой; закрытие окна до создания не добавляет пользователя.
4. Удалите игрока стандартной командой строки и сохраните: его назначение в этой команде отключено, назначения в других командах сохранены. Закрытие карточки без **«Готово»** отменяет удаление.
5. Переименуйте команду, проверьте обновление строки таблицы. Отмена, пустое и повторяющееся имя не должны изменять сохранённое название. Новая команда с ошибочными параметрами ERP не должна частично записываться.
6. В расширенных настройках добавьте и отключите назначение, сохраните адрес HTTP-сервиса ERP, соответствия и профиль. Сервисного пользователя назначать не нужно. Переключите игру и команду: таблицы и профиль должны показывать данные выбранной игры.
