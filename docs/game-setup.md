# Создание игры и настройка сохранённой игры

Откройте раздел **«Игры»**. Кнопка **«Создать»** и редактирование строки открывают одну карточку: название, сценарий, команды и их базы ERP. После создания карточка остаётся открытой для дальнейшего редактирования. Отдельных разделов создания и настройки игры нет. Правила рынка и административные параметры находятся в свёрнутых блоках.

## Новая игра

1. Нажмите **«Создать»**, укажите название и выберите сценарий. В блоке **«Правила рынка и интервалы заказов»** задайте правило создания заказов: общий рынок или персональные заказы по прайс-листам ERP. Для персональных заказов снимите флажок общего рынка и включите «Заказы по прайс-листам ERP». По умолчанию Seed = 42 и включён общий рынок.
2. В таблице уже есть **«Команда 1»** и **«Команда 2»**. Добавьте или удалите строки стандартными командами таблицы. Требуется минимум две команды с уникальными названиями.
3. Откройте **«Настроить команду»** карандашом в строке. Поле **«Наименование»** содержит текущее название: измените его и нажмите **«Готово»**. Игроки и ERP не обязательны для создания игры.
4. В блоке **«Информационные базы»** выберите **«Донастроить недостающие данные ERP»**. По умолчанию он включён: фоновая задача проверяет базы, создаёт недостающие объекты и дополняет пустые реквизиты. Снятый флажок разрешает только проверку; обнаруженное недостающее блокирует запуск.
5. Нажмите **«Создать»**. Игра, команды, назначения игроков и подключения записываются в одной транзакции. Профиль игры с календарём и начальными данными сохраняется автоматически. После успеха открыта та же карточка, кнопка меняется на **«Сохранить»**. При ошибке создания черновики остаются для исправления. После сохранения игры серверный планировщик запускает отдельное фоновое задание для каждой базы. Если ERP ещё не подключена, сохранение подключения поставит команду в очередь. Подключения с одинаковым идентификатором обслуживаются последовательно, ключ задания не превышает 60 символов.

Столбец **«Игроков»** доступен только для чтения. Значение обновляется по фактическому составу команды после нажатия **«Готово»** в её настройках.

## Существующая игра

Откройте строку в разделе **«Игры»**. Команды показаны таблицей; карандаш в строке открывает карточку с текущим наименованием, игроками и ERP. Для переименования измените поле **«Наименование»** и нажмите **«Готово»**. Команда **«Добавить команду»** в панели таблицы открывает такую же пустую карточку. Название, состав и подключение записываются в одной транзакции; закрытие карточки без сохранения отменяет изменения.

Правила, добавление и переименование команд доступны администратору до подготовки игры. Правила сохраняются кнопкой **«Сохранить»**. Отдельного блока добавления и переименования команд нет.

Через **«Открыть расширенные настройки игры»** доступны три вкладки:

- **Доступ** — таблица назначений ведущих и наблюдателей. Добавление открывается командой панели, редактирование — карандашом строки. Для отключения снимите **«Активно»** в карточке назначения. Пользователь и роль существующего назначения фиксированы; другую роль добавьте отдельной строкой.
- **ERP команды** — выбор команды, адрес HTTP-сервиса ERP для фаз и итогов и таблица соответствий номенклатуры. Сервисный пользователь Элемента не требуется; сервис использует сохранённые учётные данные ERP. Команды обновления и сохранения соответствий находятся в панели таблицы. Импорт JSON скрыт в свёрнутом блоке. Подключение ERP редактируется в основной карточке команды.
- **Профиль игры** — сохранённые календарь и начальные данные JSON, с командой сохранения.

Назначения и соответствия изменяет администратор. Переход к пульту выполняется отдельной кнопкой; настройки не запускают игру автоматически.

## Параметры общего рынка

В карточке игры при включённом общем рынке внутри **«Правила рынка и интервалы заказов»** показан блок **«Появление заказов»**. Задайте минимальное/максимальное количество единиц в заказе и минимальный/максимальный интервал в секундах. Значения по умолчанию — 1–5 шт. и 30–90 секунд. Все границы включены; совпадающие минимум и максимум задают фиксированный размер или интервал. Сохраните настройки до подготовки или запуска рынка. Параметры относятся к игре, а не к отдельной команде, и после запуска зафиксированы.

## Игроки команды

Вкладка **«Игроки команды»** содержит редактируемую таблицу активных игроков. Добавляйте строку стандартной командой таблицы и выбирайте пользователя в ячейке. Стандартная команда удаления есть в строке и для отмеченных строк. Пустые строки и повтор одного пользователя не допускаются.

Изменения таблицы применяются по общей основной кнопке **«Готово»**. Для сохранённой игры удаление строки отключает назначение пользователя в этой команде, сохраняя его назначения в других командах. Для новой игры состав сохраняется в черновике команды и записывается при создании игры. Закрытие крестиком отменяет несохранённые изменения таблицы и параметров ERP.

В сохранённой команде команда **«Создать нового пользователя»** в панели таблицы открывает отдельное окно логина и пароля. Укажите пароль длиной от 8 символов либо оставьте поле пустым для генерации. Кнопка **«Создать»** сразу создаёт пользователя, назначает его команде и добавляет строку в таблицу. Пароль показывается открытым текстом через `Сообщить()` вместе с логином. Это отдельное действие не отменяется закрытием карточки команды. При первом входе игрок меняет временный пароль.

Создание игр, изменение состава и управление пользователями доступны администратору. Ведущий может настраивать ERP своей игры без изменения списка игроков.

## База ERP команды

1. Введите **адрес публикации ERP**, затем **логин** и **пароль**. Полный адрес OData формируется автоматически добавлением `/odata/standard.odata/`.
2. После изменения пароля система загружает доступные организации. Для повторной загрузки есть кнопка **«Загрузить организации»**. Список читается из ERP, с учётом прав указанного пользователя, без помеченных на удаление организаций и с постраничным чтением.
3. Выберите организацию из списка. Произвольный ввод запрещён. Если выбор пуст и организация одна, она выбирается автоматически. Смена адреса базы очищает выбор; смена логина или пароля сохраняет выбранное название и требует проверки списка перед записью новых параметров.
4. Нажмите общую кнопку **«Готово»**, чтобы сохранить ERP вместе с составом команды. Отдельной кнопки сохранения базы нет. При ошибке окно остаётся открытым, введённые данные сохраняются для исправления.

При открытии сохранённой команды организация сразу берётся из настроек; запрос ERP при открытии не выполняется. Ошибка загрузки организаций не стирает сохранённый выбор. Ввод адреса, логина и пароля, успешная загрузка организаций и автоматический выбор единственной организации не вызывают всплывающих уведомлений: подсказка показана во вкладке ERP. Ошибки запроса и сохранения показываются через `Сообщить()`. Если выбранная организация отсутствует в новом ответе ERP, форма показывает подсказку и сохраняет название для проверки; изменённые параметры нельзя записать, пока не выбрана доступная организация.

В сохранённой команде показывается адрес публикации без OData-суффикса. Сохранённый пароль не возвращается на клиент: пустое поле сохраняет его при неизменном адресе и логине. Для получения организаций сервер использует сохранённый секрет. При изменении адреса или логина требуется новый пароль. Неизменное сохранённое подключение позволяет записать изменения состава даже при недоступной ERP. Команда без подключения не требует заполнения ERP для изменения имени или игроков.

Каждая команда игры использует отдельный адрес ERP. После подготовки адрес и организацию менять нельзя. Кнопка **«Подготовить или проверить базу»** работает с уже сохранённым подключением. В открытом окне команда и организация уже выбраны, пустой пароль использует сохранённый секрет. После «Создать необходимые данные» или чтения готовой базы все 15 идентификаторов ERP сохраняются автоматически для этой команды; новые параметры сначала запишите через **«Готово»**. Полный цикл игры требует HTTP-сервиса расширения ERP по [исходящему контракту](erp-pull.md). Адрес сервиса задаётся на вкладке «ERP команды» расширенных настроек; по умолчанию используется `/hs/game/v1/` этой базы.

## Проверка после публикации

1. Откройте карандашом команду с настроенной ERP: организация видна сразу. Закройте и откройте её повторно, в том числе при недоступной ERP. Измените только имя или состав игроков и сохраните — организация должна остаться прежней.
2. Смените пароль ERP: после успешной загрузки прежняя доступная организация остаётся выбранной. При ошибке или отсутствии организации в ответе название не исчезает, новые параметры нельзя сохранить. Смена адреса очищает выбор.
3. Создайте пользователя через панель таблицы: проверьте строку игрока, сообщение с логином и открытым паролем, затем первый вход. Повторный логин и короткий пароль оставляют окно открытым с ошибкой; закрытие окна до создания не добавляет пользователя.
4. Удалите игрока стандартной командой строки и сохраните: его назначение в этой команде отключено, назначения в других командах сохранены. Закрытие карточки без **«Готово»** отменяет удаление.
5. Переименуйте команду, проверьте обновление строки таблицы. Отмена, пустое и повторяющееся имя не должны изменять сохранённое название. Новая команда с ошибочными параметрами ERP не должна частично записываться.
6. В расширенных настройках добавьте и отключите назначение, сохраните адрес HTTP-сервиса ERP, соответствия и профиль. Сервисного пользователя назначать не нужно. Переключите игру и команду: таблицы и профиль должны показывать данные выбранной игры.

## Спрос в процентах

В карточке игры в блоке правил рынка задайте **«Спрос рынка, % доступного объёма игроков»**: 1–100%, до двух знаков после запятой, по умолчанию 80%. Сохраните до подготовки игры. Спрос рассчитывается от доступных остатков активных команд из ERP, с округлением до целой единицы. При персональных заказах процент применяется к общему объёму всех моделей текущего раунда; при общем рынке — к объёму модели при её первом заказе. Цена влияет на распределение, но не на общий процент спроса.

## Фоновая настройка и доступность игры

Состояние каждой команды видно в настройке игры: «Ожидает», «Выполняется», «Готова» или «Ошибка» с причиной. Форма и пульт обновляют состояние каждые 5 секунд и сообщают о завершении. Результат сохраняется в команде и истории событий; закрытие формы не останавливает работу. В состоянии «Готова» подтверждены НСИ, начальные данные и все 15 соответствий номенклатуры. Дополнительные ручные настройки планирования, калькуляции и счетов учёта перечислены отдельно: готовность НСИ не означает их автоматическое выполнение.

Пока хотя бы одна активная команда не прошла проверку, кнопки запуска недоступны. Сервер также отклоняет подготовку, начало полной игры и запуск рынка OData. **«Проверить базы»** повторно ставит базы в очередь с выбранным режимом проверки/донастройки. Повтор разрешён после завершения текущей работы; проверка действующей базы не создаёт повторных начальных документов. Непустые конфликтующие значения ERP не перезаписываются.

После изменения адреса, организации или учётных данных подключения в черновике готовность сбрасывается и запускается новая проверка. Во время настройки параметры ERP команды менять нельзя. При прерывании сервера незавершённое задание восстанавливается после истечения 30-минутной аренды; запоздалый ответ прежнего задания не может отметить новую настройку готовой.

## Принудительное завершение этапа

В пульте ведущего у открытого этапа идущей игры есть **«Завершить этап принудительно»**. Укажите причину в открывшемся окне. Дедлайн сокращается до текущего момента, прекращается появление заказов, фиксируются текущие итоги и заявления незавершивших команд с именем ведущего и причиной. Досрочные заявления игроков сохраняются. Следующая фаза открывается отдельной обычной командой после проверки прайс-листов, заказов и фактов ERP.

## Сценарий и сообщения об ошибках

Начальные количества ресурсов, себестоимость и продажные цены берутся из выбранного сценария; случайные количества используют seed игры и тот же алгоритм, что подготовка игры. Эти условия применяются к документам остатков и цен ERP. Вся номенклатура учебного профиля создаётся при настройке, даже если у неё нет начального остатка в сценарии. В документы ввода остатков попадают только положительные количества, указанные в сценарии; отсутствующие ресурсы и нулевые количества не добавляются. Пустые документы остатков не создаются. Например, отсутствие `FRAME_STD` означает нулевой стартовый запас стандартных рам, а не запрет создания номенклатуры. Во внутреннем пакете обмена все 26 пар номенклатура/склад сохранены, отсутствующие заполнены нулями; цены для номенклатуры без стартового запаса остаются из учебного профиля. Деньги и долг поставщику остаются общими условиями учебного профиля, поскольку сценарий их не задаёт.

Смена сценария или seed в черновике пересоздаёт профиль и ставит базы на повторную проверку. Во время выполняющейся настройки смена запрещена. Кнопка **«Проверить базы»** сначала сохраняет правила карточки. Ручная подготовка из команды использует её базу, организацию и дату из календаря игры. Проведённые документы с несовместимыми условиями не перезаписываются: требуется другая чистая база или исправление исходных данных.

Все ошибки пользовательских форм выводятся через `Сообщить()`, включая проверку полей, удаление, обмен и автоматическое обновление. Ошибки фоновой подготовки показываются с именем команды и причиной сразу при получении статуса. Повтор одной ошибки таймера не создаёт уведомление каждые пять секунд; после восстановления связи новая ошибка снова показывается. Отчёты и история сохраняют диагностические подробности.
