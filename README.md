# Администрирование экономической игры на 1С

Приложение на **1С:Предприятие.Элемент 10.0** для проведения учебной игры в 1С:ERP. Исходники находятся в `dimkashelk/Игра`.

После создания игры базы команд проверяются и донастраиваются фоновыми заданиями. Мастер спрашивает разрешение на создание недостающих данных; ход работ и уведомление о результате видны в настройках и пульте. До успешной проверки всех активных баз запуск заблокирован.

Ведущий создаёт игру, настраивает сценарий, команды, пользователей и подключения ERP, управляет фазами и публикует рейтинг. Игроки работают в своих ERP и получают заказы через кабинет. ERP служит источником фактических остатков, продаж, оплат и денег. После полной отгрузки команда нажимает «Закрыть заказ» в ЛК: Элемент проверяет складские движения, создаёт и проводит банковское поступление через OData, подтверждает оплату и затем закрывает заказ.

Реализованы серверные ограничения и права, версионирование сценариев, подготовка игры, два алгоритма распределения рынка, общий пул заказов, пульт ведущего, исходящий обмен OData + HTTP ERP 1.0, настройка баз через OData, диагностика обмена, сверка периодов и результаты команд.

Игра обращается к ERP под сохранёнными учётными данными базы; сервисный пользователь Элемента не нужен. Серверный опрос работает каждые 5 секунд без открытого пульта или диагностики; команды опрашиваются отдельными заданиями. Для фаз и итогов требуется опубликованный HTTP-сервис расширения ERP по новому контракту. Подготовка и переходы между фазами требуют проверенных результатов ERP. Рейтинг строится по подтверждённым денежным остаткам. Расчётная выручка рынка не заменяет фактические оплаты.

Для отдельной работы с рынком используйте **«Пульт → Запустить только рынок OData»**: команды получают заказы в кабинете, приложение создаёт и проводит заказы клиента в их базах. Снимки и HTTP-сервис расширения ERP для этого режима не требуются. Общая цена новых заказов зависит от спроса и свободных остатков всех команд; размеры партий и интервалы задаются в игре. [Порядок настройки](docs/player-cabinet.md#только-рынок-и-odata).

**Новый режим «Заказы по прайс-листам ERP»**: команды сначала устанавливают цены в своих базах, затем Элемент распределяет спрос и выдаёт каждой один персональный многострочный заказ. Общий спрос не меньше числа команд, а на старте строго меньше общего доступного остатка. После выполнения заказов продолжается цикл планирования, закупок и производства. [Правила и запуск](docs/market.md#заказы-по-прайс-листам-erp).

## Служебные инструменты

`scripts/setup_erp_odata.py` подготавливает базу ERP; `scripts/read_erp_market.py` читает цены и остатки. `scripts/generate_game_contract.py` создаёт контракт и модуль схем по нормативным таблицам; `scripts/generate_odata_setup_profile.py` создаёт модуль профиля OData. Скрипты используют стандартную библиотеку Python 3.

Раздел **«Игры»** объединяет создание и редактирование в одной карточке. Настройка ERP создаёт необходимую номенклатуру, а остатки вводит только в положительных количествах из выбранного сценария. Подсказки при вводе реквизитов ERP показаны в форме, ошибки — через `Сообщить()`. В кабинете игрока рынок и готовность команды находятся на отдельных вкладках. В боковом меню «Аналитика рынка» доступны история выполненных продаж по моделям и раундам, индивидуальные цены и оценка маржи команды, средневзвешенные цены и объёмы всех команд. Подробнее: [настройка игры](docs/game-setup.md).
